## 1. Краткое резюме

Пакет отчётов был загружен в сервис, он обработал все файлы без видимых ошибок. Но по содержанию результат тревожный:

- **Из 21 загруженного файла 20 (95 %) вернули 0 распознанных конструкций.**
- Содержательный результат получен только по **одному** отчёту (№ 13): 14 конструкций, из них 4 аварийных, выдана угроза обрушения.
- Все 20 «пустых» отчётов получили приоритет **«НИЗКИЙ»** и зелёный индикатор, то есть сервис молча превратил отсутствие данных в вывод «опасности нет».

Это главный вывод первого прогона: **сервис не отличает «ничего не найдено» от «всё в порядке»**.

| № | Наблюдение | Тип | Серьёзность |
|---|---|---|---|
| P1 | Нулевой результат по 95 % файлов | Распознавание / ПРОПУСК | Критическая |

| P5 | Нет индикации типа файла (текстовый/скан), числа страниц, объёма извлечённого текста | Диагностика | Средняя |

## 4. Гипотезы о причинах нулевого результата

| # | Гипотеза | Как проверить |
|---|---|---|
| H1 | Часть файлов — **сканы**, текстового слоя нет, OCR не отработал (путь к Tesseract задан жёстко, возможна тихая ошибка) | Открыть PDF, попытаться выделить текст; посмотреть логи OCR |
| H2 | **Сломано разбиение на разделы**: заголовки ищутся по `\n`, а текст слит в одну строку, поэтому разделов с конструкциями не находится | Вывести число найденных разделов для 2–3 «пустых» отчётов |
| H3 | Конструкции ищутся по узкому списку слов; в реальных отчётах используются другие формулировки | Сравнить текст отчёта со словарями `01_constructs` |
| H4 | Фильтры `'см'`/`'рис'` по подстроке вырезают нужные фрагменты | Проверить, сколько текста остаётся после фильтрации |
| H5 | Ошибка при обработке подавляется (try/except), результат записывается как «0» | Просмотреть код и логи на перехват исключений |
| H6 | Отчёт № 13 отличается по структуре (текстовый PDF, стандартные заголовки), потому и обработан | Сравнить формат № 13 с «пустыми» |

## 5. Что известно и что неизвестно

**Известно:**
- пакетная загрузка работает, все файлы обработаны и сохранены в истории;
- интерфейс показывает счётчики по категориям, приоритет и угрозу;
- формально функция «выявить аварийное здание» сработала хотя бы один раз (№ 13).

**Неизвестно (нужны данные):**
- верен ли результат по № 13 (нужна сверка с эталоном);
- какие из 20 «пустых» отчётов на самом деле содержат конструкции и дефекты, а какие действительно пусты;
- сколько среди них сканов;
- сколько аварийных зданий пропущено.

## 6. План дальнейшего анализа

1. **Диагностика пустых отчётов.** Для 3–5 файлов вывести: тип PDF, число страниц, длину извлечённого текста, число разделов, число найденных конструкций.
2. **Эталон.** Для каждого из 21 файла вручную зафиксировать итоговый статус здания по заключению в самом отчёте, список конструкций и аварийные дефекты.
3. **Детальная проверка № 13.** Открыть «Показать детали», сверить каждую из 14 конструкций с оригиналом: цитата, страница, категория, размеры.
4. **Метрики.** Построить матрицу ошибок по статусам, подсчитать число пропущенных аварийных случаев (FN-авария) и долю верных статусов.
5. **Переименовать файлы** понятным образом или вести реестр «хеш → оригинальное имя».

Подробный шаблон протокола (матрица функций, реестр ошибок, 25 гипотез, метрики) находится в файле `README.md`.

## 8. Ограничения этого документа

- Выводы основаны только на трёх скриншотах итоговых экранов; содержимое самих отчётов и детальные экраны не анализировались.
- Причины нулевого результата пока являются гипотезами.
- Оценка правильности результата по № 13 невозможна без эталонной разметки.
- Сервис — помощник эксперта и не заменяет заключение специалиста, особенно для аварийных зданий.
